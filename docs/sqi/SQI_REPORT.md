# SQI — Software Quality Improvement Index: rust-less (`rless`)

Evaluation date: 2026-11-04. Baseline commit: `47c8784`.
The rubric, weights, measurement methods, task set and screen conditions
(§1–§3) were fixed **before any code change** and were not edited afterwards.
§4 is the baseline. §5 (after) is appended at the end of the work.

## 1. Scope and conditions (fixed)

- Product: terminal pager (Rust 2024, crossterm TUI). Two layers:
  - **Core pager**: a parity clone of GNU less 668. Its screen output is a
    *contract*, checked byte for byte by `make parity` (40 scenarios). Visual
    changes to this layer are **out of scope by contract**: changing them would
    break parity. The core is scored as it is, and any change there must keep
    40/40.
  - **Structured-log extension** (PR #1): sniffer, tabular / expanded
    projection, `&` filter, selector queries, column mode. Change is allowed here.
- VQI and UXQI apply. The UI is a character-cell TUI, so "screen" means a tmux pane.
- Screen conditions: tmux pane 80x24 (T12 uses 50x10), `LANG=C.UTF-8`, the
  default theme of the terminal, and the fixtures generated by
  `docs/sqi/ux_probe.py`, which are deterministic.
- Weights: the default 0.25 × 4. All four areas are in scope.
- Evidence levels: E0 = not verified, E1 = code reading, E2 = reproducible
  script or test, E3 = measurement (bench) or the parity oracle.

## 2. Measurement instruments (fixed)

| ID | Instrument | What it gives |
|---|---|---|
| M1 | `cargo test`, `make lint` (fmt + clippy -D warnings) | Correctness, lint |
| M2 | `make parity` (tmux, 40 scenarios vs the captured less 668 baseline) | Contract non-regression (E3) |
| M3 | `docs/sqi/ux_probe.py`: 17 scripted tasks, one per user-visible feature | Task success rate (E2, **not a user test**) |
| M4 | `docs/sqi/static_metrics.sh` | Structural counts (E2) |
| M5 | `make bench` (pinned with `taskset -c 0`, p50) | Latency and memory (E3) |

Performance normalisation (UXQI 7.7). The score for each operation is
`clamp(5 × (U − p50) / U, 0, 5)`, where U = 100 ms for a per-keystroke
redraw (Nielsen's "instantaneous" limit) and U = 1000 ms for a whole-file
operation on 1M lines (Nielsen's "flow" limit). The item score is the mean
over the 7 benches.

Task success (UXQI 7.1): the score is `5 × passed / 17`.

## 3. Rubric (fixed). Each item is scored 0–5; area score = Σ weight × score / 5

General anchors: 0 = fails the requirement, 1 = several severe defects,
2 = basic structure with recurring defects, 3 = meets the basics,
4 = consistently high quality, 5 = 4 plus edge cases proven by evidence.

## 4. Baseline (before), commit 47c8784

### 4.1 Measurements

- M1: 80 tests passed, 9 ignored (benches), 0 failed. fmt and clippy are clean.
- M2: parity **40/40** (scenarios 40, passed 40).
- M3: **6/17 tasks (35.3 %)**. Failures, each reproduced on screen:
  - T04: a plain-text search for `.status >= 500` is parsed as a selector →
    "Pattern not found", but less finds it. This breaks the stated design
    intent ("100% parity fallback for plain text").
  - T07: `n` after a structured search does nothing, because `last_search`
    is never set.
  - T09: an invalid `&(unclosed` filter blanks the whole view and reports no error.
  - T10: CSV tabular view adds phantom empty columns `col_1..3`, and its
    widths come only from the header, so values are truncated (`ali…`).
  - T11: the format is sniffed only for the first file. After `:n`, a CSV
    file is projected with JSONL columns, so the table never appears.
  - T12: at 50 columns, table rows are written past the pane width and spill
    into the prompt row (`View mode: tabular handled   │`).
  - T13: the sticky header ignores pinned columns, so after `p` the labels
    sit over the wrong data.
  - T14 and T15: column mode shows only `col N`. The decoder's own index can
    pass the column count (`col 9` of 6) and drifts from `App.focused_column`.
  - T16: pin, hide and sort messages are overwritten by the column-mode
    preview and are never visible.
  - T17: **security**. In tabular, expanded and filtered views, file bytes
    are printed raw. BEL rings and CR moves the cursor (`cr\rXX` overwrote
    the row), whereas the core view shows `^G` / `^M`.
  - Also seen by reading code: the sort key (`s` in column mode) reports
    `[SORT: … (snapshot)]` but sorts nothing. A filter on plain text reports
    `Filter: &…` but has no effect. The projection path drops I/O errors
    (`if … .is_err() { break }`). With a sticky header, `-M` reports a
    `bottom_line` one row too far. The expanded JSON view prints a trailing
    `,` after the last field. Prompt truncation counts chars, not display
    width.
- M4: 9 scanner dispatch calls across 2 modules, and 4 format `match` sites
  outside sniffer/simd. 3 `allow(dead_code)`. 5 `pub` fields on `App`, none
  needed: bench and tests use in-module access or hooks. 2 never-read
  fields (`sorted_by_column`, `projection_index`). 2 prompt-mode enums.
  `draw_frame` is 158 lines. 0 control-character sanitisers on projection
  output.
- M5 (p50): see §6.
